## Задача 11 Начальник отдела.
### Текст задачи
Измените сущности полученные в задаче 1.2.4. Необходимо гарантировать, что начальник отдела
гарантированно работает в том же отделе, в котором он начальник.
### Алгоритм решения
Реализовано в отдельной ветке "1.11".
Для гарантии, что глава отдела всегда работает в этом-же отделе пришлось сделать:
1) В классе Department для методов меняющие значения полей сделано:
    - getEmployees() теперь возвращает не сам список employees, а его копию, заполненную теми-же сотрудниками;
    - setHead(Employee head): если передана пустая ссылка, то просто присваивает полю head null, иначе проверяет совпадение отдела работы сотрудника с данным отделом, если да, то сохраняет ссылку в поле head, в противном случае возвращает ошибку не меняя поля;
    - addEmployee(Employee employee) обрабатывает 5 сценария для переданного сотрудника:
      1) передана пустая ссылка - возвращаем сообщение об ошибке;
      2) передан сотрудник ещё не принадлежащий отделу - добавляем его в список работников и для сотрудника вызываем метод setDepartment(this);
      3) передан сотрудник у которого уже присвоен ДРУГОЙ отдел - возвращаем сообщение об ошибке;
      4) передан сотрудник у которого уже присвоен этот отдел, но в списке работников отдела он ещё не добавлен (это происходит когда вызов метода сделан из метода Employee.setDepartment(Department department)) - тогда просто добавляем сотрудника в список работников отдела;
      5) передан сотрудник у которого уже присвоен этот отдел и он уже есть в списке работников (повторное добавление) - возвращаем сообщение об ошибке;
    - removeEmployee(Employee employee) обрабатывает 5 сценария для переданного сотрудника:
      1) передана пустая ссылка - возвращаем сообщение об ошибке;
      2) передан сотрудник являющийся главой отдела - возвращаем сообщение об ошибке;
      3) передан сотрудник не работающий в отделе - возвращаем сообщение об ошибке;
      4) передан сотрудник у которого поле department уже null (это происходит когда вызов метода сделан из методов Employee.setDepartment(null) или Employee.nullDepartment()) - удаляем сотрудника из списка работников отдела;
      5) передан сотрудник у которого поле department ещё присвоено исходному отделу - удаляем его из списка работников и вызываем метод employee.setDepartment(null);
2) В классе Employee для методов меняющие значения полей сделано:
    - setDepartment(Department department) обрабатывает 4 сценария:
      1) передана пустая ссылка - вызываем метод nullDepartment();
      2) сам работник уже работает в каком-либо отделе - возвращаем сообщение об ошибке;
      3) сотрудник пока не относится ни к одному отделу, но уже зачислен в список работников переданного отдела(вызов метода сделан из метода Department.addEmployee(Employee employee)) - записываем ссылку на отдел в поле department;
      4) сотрудник пока не относится ни к одному отделу и не находится в списке работников отдела - записываем ссылку на отдел в поле department и вызываем метод department.addEmployee(this);
    - nullDepartment() обрабатывает 4 сценария:
      1) поле department уже null - возвращаем сообщение об ошибке;
      2) сотрудник является главой своего отдела - возвращаем сообщение об ошибке;
      3) обычный сотрудник отдела, в списке работников отдела уже не числится(вызов данного метода из метода Department.removeEmployee(Employee employee)) - просто присваиваем полю department null;
      4) обычный сотрудник отдела, ещё числиться в списке работников отдела - присваиваем полю department null и вызываем метод department.removeEmployee(this) (для вызова, перед обнулением ссылки сохраняем отдел в переменную olddepartment);

# Задание 2
## Задача 4 Бинарное дерево.-
### Текст задачи
Необходимо реализовать структуру данных, представляющую собой простейшее бинарное
дерево. Для формирования данного дерева будет использоваться сущность Узел.
Состояние сущности описывается следующими характеристиками:
- Значение, целое число
- Родитель, Узел
- Левый потомок, Узел
- Правый потомок, Узел.

Инициализация сущности выполняется без аргументов.\
Поведение сущности описывают следующие действия:
- Добавление значения. При добавлении значения возможно две ситуации
  - Для данного узла Значение не было задано ранее. В этом случае оно задается и
  работа завершается
  - Для данного узла Значение ранее было задано. В этом случае определяется, больше
  ли новое значение или меньше-равно чем текущее. Если больше – то значение
  добавляется в правый потомок, иначе в левый. Если нужный потомок отсутствует,
  то сначала он должен быть создан.
- Удаление значения. В качестве аргумента передается значение, которое нужно удалить.
Если такое значение есть, в самом узле или любом его потомке, то удаляется узел с этим
значением, но все его потомки должны остаться прикрепленными к структуре.
- Проверка на существование значения. В качестве аргумента передается значение, и
возвращается информация о том есть ли такое значение в самом узле или любом его
потомке.
- Приведение к строке. Результатом приведения узла к строке является перечень всех
значений хранимых в данном узле и всех его потомках, которое должно быть получено
левосторонним обходом в глубину.

После реализации сущности, создайте её экземпляр и добавить в него числа: 3 5 4 7 1 2. Выведите
на экран текстовое представление узла.
### Алгоритм решения
Реализация через класс Node, поля в нём согласно условию + 1 новое поле initialized которое хранит информацию о наличие значения у узла.
Имеет 2 конструктора:
1) публичный без принимаемых значений, необходим изначального создания структуры, initialized ставится на false.
2) непубличный, принимает 2 значения: value и parent; используется внутренними методами для создания левых и правых потомков.

Реализует методы:
1) addValue
2) deleteValue
   1) getDeleteMaxLeft
   2) getDeleteMaxRight
3) checkValue
4) toString

## Задача 1 Отделы доверяют начальникам.
### Текст задачи
Данная задача предполагает, что в результате выполнения 2.7.1, сущности Отдел и Сотрудник
(задача 2.1.11) попали в один и тот же пакет. Ранее было выдвинуто требование о том, что
Начальник отдела всегда работает в том же Отделе в котором он руководит. При реализации
инкапсуляции на уровне класса это требование приводит к неэффективному и запутанному коду.
Упростите решение, предполагая что инкапсуляция необходима только на уровне пакета.
### Алгоритм решения
Для инкапсуляции на уровне пакета классы Department и Employee изменены.\
Employee:
- более нет публичных методов для смены значений параметров, изменения значения для поля department только через методы класса Department.
- метод nullDepartment() более не нужен и удалён
- метод setDepartment(Department department) сразу меняет отдел на заданный без проверок; все проверки делаются в методах класс Department.

Department:
- addEmployee(Employee employee) обрабатывает 3 сценария:

  2) передан сотрудник, который уже работает в каком-либо отделе - возвращаем сообщение об ошибке;
  3) передан сотрудник с полем department == null - добавляем его в список работников отдела и вызываем метод employee.setDepartment(this);
- removeEmployee(Employee employee) обрабатывает 4 сценария:
  1) передан null - возвращаем сообщение об ошибке;
  2) передан сотрудник, который является главой отдела - возвращаем сообщение об ошибке;
  3) передан сотрудник, который не является сотрудником отдела - возвращаем сообщение об ошибке;
  4) передан обычный сотрудник отдела - удаляем его из списка работников и вызываем метод employee.setDepartment(null).
